# 문의 중복 확인과 검토

휴대폰 번호로 같은 고객을 판정합니다. 하이픈·공백·괄호와 국내 휴대폰의 +82/0082 표기를 동일하게 정규화합니다. 이름이 같거나 다른지는 등록 허가 조건이 아닙니다. 같은 번호의 미전송 문의는 검토 전까지 모두 보류합니다. 이미 등록된 기록은 보존합니다.

1. 수집 문의 중복 또는 전송 전 WARP 읽기 전용 조회에서 기존 고객이 확인되면 `중복확인`으로 표시하고 신규 고객 등록 요청을 보내지 않습니다. 조회가 실패·누락되면 전송을 중단합니다. 조회 이후 고객이 추가되는 경쟁 상황도 WARP 등록 트랜잭션에서 차단합니다.
2. `중복확인`은 상태 표시이며 버튼이 아닙니다. 별도 `검토하기`에서 같은 번호의 수집 문의와 중복 사유를 봅니다. WARP 고객관리 링크에서 기존 고객을 확인합니다.
3. 관리자는 내용을 확인하고 체크박스에 동의한 뒤 `검토완료 · 전송 보류`로 정리할 수 있습니다. 고객·원본 문의·전송 영수증은 삭제하거나 수정하지 않습니다. 일반 사용자는 조회만 가능합니다.
4. WARP에서 고객 통합/연락처 정정 등 필요한 업무를 처리한 후 `중복 재확인`을 요청할 수 있습니다. 살아 있는 수집기가 읽기 전용으로 다시 조회하며 실패하거나 여전히 중복이면 전송을 보류합니다. 문의나 비교 대상이 바뀌면 이전 검토 확인은 거절합니다.
5. 재확인으로 중복이 해소돼도 자동 전송하지 않습니다. `등록 검토` 상태에서 내용을 확인한 다음 `등록하기`를 별도로 누릅니다. 연락처 정정은 원본 운영 담당자에게 요청하며 기존 문의를 재수집한다고 보장하지 않습니다.
6. 같은 번호의 수집 문의만 있고 기존 WARP 전송 증거나 다른 등록 요청이 없으면, 관리자는 남길 문의의 검토창에서 별도 확인 후 `이 문의를 대표로 등록`을 누릅니다. 이 명시적 요청은 대표 1건을 등록 대기열에 넣고 나머지 문의를 해당 대표에 연결합니다. 이전에 전송 보류한 문의도 선택할 수 있으며 원본 이름·번호·일시·전송 증거는 보존합니다.
7. 수집기가 대표의 WARP 고객·리드 존재 여부를 읽기 전용으로 조회한 뒤, 없다는 응답을 검증한 경우에만 기존 등록 경로로 전송합니다. 조회 실패·불완전 응답·기존 고객이 있으면 보류합니다. 등록 응답이 유실되면 같은 대표의 영수증을 조회해 복구하며 다른 문의로 바꾸어 재전송하지 않습니다.
8. 고객·리드 완료 영수증을 확인한 대표는 `고객·리드 등록완료`, 연결 문의는 `중복 문의 · 대표 건 등록완료`로 표시합니다. 연결 문의에는 별도 등록 버튼을 노출하지 않으며 등록완료 건수·DB 유입 집계에 추가하지 않습니다. 동시에 다른 대표를 선택하거나 검토 이후 문의가 바뀌면 이전 요청은 거절합니다. 선택 이후 같은 번호의 신규 문의가 추가되면 전송 직전 검사가 보류하며, 대표 검토창에서 갱신된 문의 목록을 확인하고 다시 요청할 수 있습니다.
9. 연결은 기존 상태 필드의 `warp_duplicate_of:<대표 문의 ID>`로 보존합니다. 대표가 삭제되거나 연락처가 바뀌어 연결이 불명확해지면 보류하며 자동으로 다른 문의를 선택하지 않습니다. 대표 선택·등록은 기존 관리자/동일 출처/검토 토큰 검증과 worker lease를 그대로 사용합니다. DB 스키마와 WARP API 계약은 변경하지 않습니다.

WARP에서 확인된 휴대폰 중복을 보류하면 `warp_duplicate_evidence_reviewed`로 근거를 유지합니다. 이를 단순 수집 문의 중복으로 취급해 다른 문의를 대표 등록할 수는 없습니다. WARP 측 정정 후 읽기 전용 재확인으로 중복이 해소된 경우에만 등록을 다시 검토합니다. 문의 연락처를 변경하는 기능은 없으며, 운영 DB를 직접 수정하는 절차는 이 기능의 지원 범위가 아닙니다.

## 배포와 호환성

WARP 수신기/조회 API를 먼저 공식 release로 배포하고 Marketing을 이후 배포합니다. 두 저장소의 WARP_MARKETING_INQUIRIES.json은 동일해야 합니다. 기존 API 키와 고정 회사 범위를 사용하며 추가 권한이나 비밀값은 만들지 않습니다. DB 스키마 변경은 없습니다. 기존 warpError 상태에 검토/재확인/해소 여부를 저장합니다.

Marketing 롤백 시 새 검토 상태를 이전 프로그램이 모르는 제약이 있습니다. 현재 운영 설정은 자동 등록 비활성이므로 보류 상태의 자동 재전송을 막습니다. 롤백을 계획할 때 이 설정을 확인하고 이전 UI에서 검토 상태 문의의 수동 등록을 요청하지 않습니다. WARP 롤백으로 조회 API가 없어져도 새 Marketing은 조회 실패로 전송을 중단합니다. 운영 고객 통합과 연락처 변경은 자동으로 수행하지 않습니다.

검증은 합성 DB/계정/연락처로 수행합니다. 운영 확인에서는 로그인·검토 정보 조회·읽기 전용 연동·런타임/수집기 상태만 확인하며 실제 문의를 테스트 목적으로 등록하거나 보류하지 않습니다.
