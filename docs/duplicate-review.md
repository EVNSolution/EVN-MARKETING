# 문의 중복 확인과 검토

휴대폰 번호로 같은 고객을 판정합니다. 하이픈·공백·괄호와 국내 휴대폰의 +82/0082 표기를 동일하게 정규화합니다. 이름이 같거나 다른지는 등록 허가 조건이 아닙니다. 수집된 문의 중 같은 번호는 먼저 수집된 문의를 기준으로 이후 문의를 보류합니다. 이미 등록된 기록은 보존합니다.

1. 수집 문의 중복 또는 전송 전 WARP 읽기 전용 조회에서 기존 고객이 확인되면 `중복확인`으로 표시하고 신규 고객 등록 요청을 보내지 않습니다. 조회가 실패·누락되면 전송을 중단합니다. 조회 이후 고객이 추가되는 경쟁 상황도 WARP 등록 트랜잭션에서 차단합니다.
2. `중복확인`은 상태 표시이며 버튼이 아닙니다. 별도 `검토하기`에서 같은 번호의 수집 문의와 중복 사유를 봅니다. WARP 고객관리 링크에서 기존 고객을 확인합니다.
3. 관리자는 내용을 확인하고 체크박스에 동의한 뒤 `검토완료 · 전송 보류`로 정리할 수 있습니다. 고객·원본 문의·전송 영수증은 삭제하거나 수정하지 않습니다. 일반 사용자는 조회만 가능합니다.
4. WARP에서 고객 통합/연락처 정정 등 필요한 업무를 처리한 후 `중복 재확인`을 요청할 수 있습니다. 살아 있는 수집기가 읽기 전용으로 다시 조회하며 실패하거나 여전히 중복이면 전송을 보류합니다. 문의나 비교 대상이 바뀌면 이전 검토 확인은 거절합니다.
5. 중복 해소 후에도 자동 전송하지 않습니다. `등록 검토` 상태에서 내용을 확인한 다음 `등록하기`를 별도로 누릅니다. 아직 같은 번호의 수집 문의가 있으면 보류 상태를 유지합니다. 연락처 정정은 원본 운영 담당자에게 요청하며 기존 문의를 재수집한다고 보장하지 않습니다.

## 배포와 호환성

WARP 수신기/조회 API를 먼저 공식 release로 배포하고 Marketing을 이후 배포합니다. 두 저장소의 WARP_MARKETING_INQUIRIES.json은 동일해야 합니다. 기존 API 키와 고정 회사 범위를 사용하며 추가 권한이나 비밀값은 만들지 않습니다. DB 스키마 변경은 없습니다. 기존 warpError 상태에 검토/재확인/해소 여부를 저장합니다.

Marketing 롤백 시 새 검토 상태를 이전 프로그램이 모르는 제약이 있습니다. 현재 운영 설정은 자동 등록 비활성이므로 보류 상태의 자동 재전송을 막습니다. 롤백을 계획할 때 이 설정을 확인하고 이전 UI에서 검토 상태 문의의 수동 등록을 요청하지 않습니다. WARP 롤백으로 조회 API가 없어져도 새 Marketing은 조회 실패로 전송을 중단합니다. 운영 고객 통합과 연락처 변경은 자동으로 수행하지 않습니다.

검증은 합성 DB/계정/연락처로 수행합니다. 운영 확인에서는 로그인·검토 정보 조회·읽기 전용 연동·런타임/수집기 상태만 확인하며 실제 문의를 테스트 목적으로 등록하거나 보류하지 않습니다.
