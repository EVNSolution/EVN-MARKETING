# 수집 후 관리중 처리와 문의별 WARP 등록

2026-09-29 사용자 요청에 따라 기존 조회 전용 수집기에 원본 상태 변경을 추가한다. 로컬 문의 저장이 커밋된 뒤 원본의 같은 회사·홈페이지·문의 UUID·연락처를 확인하여 `접수` 또는 상태 미지정 문의만 `관리중`으로 변경한다. 이미 관리중이거나 다른 상담 상태인 문의는 유지한다. 저장 후 원본을 새로 불러와 결과를 확인하며, 실패하면 수집을 부분 완료로 남기고 다음 실행에서 다시 확인한다. 기존 신규 문의 중심 수집 범위는 유지하며, 과거 문의 전체를 매시간 재조회하지 않는다. Marketing의 상담상태는 수집 당시 원본 기록으로 보존한다.

문의 내역의 마지막 열은 `WARP CRM`이다. 전송 확인 기록이 있으면 `등록완료`, 관리자의 미등록 문의에는 `등록하기` 버튼을 표시한다. 등록완료는 해당 문의가 WARP 고객과 문의 이력에 연결되었다는 뜻이며 WARP 전체 고객의 현재 존재 여부를 실시간 조회한 결과는 아니다. WARP가 동일 연락처의 기존 고객을 찾으면 기존 정보를 유지하고 문의 이력을 연결한다. 연락처가 같은 고객이 여러 명이면 기존 충돌 응답을 그대로 보류한다.

버튼 요청은 관리자·동일 출처·회사 범위를 검증하고 기존 전송 상태에 `warp_manual_requested`를 저장한다. 살아 있는 수집기만 요청을 받으며, 유효한 작업 권한과 worker lease를 가진 수집기가 기존 WARP 키로 전송한다. 웹에 API 키를 추가하지 않는다. 등록중에는 버튼을 비활성화하고 수신 확인 후 완료로 전환한다. 이미 전송한 문의의 재요청은 재전송하지 않는다. DB 스키마와 외부 WARP 요청 형식은 변경하지 않는다.

자동 등록이 꺼진 상태에서는 명시적으로 요청한 문의만 전송한다. 실패 시 다시 버튼으로 요청해야 하며 기존 연결 오류의 1시간 대기는 유지한다. 이름이 없는 문의는 WARP의 신원미상 이름 규칙 배포 검증 및 자동 등록 활성화 전까지 웹과 수집기 양쪽에서 차단한다. 관련 수신부 변경은 EVNSolution/EVN-WARP PR #50이다.

## 검증 및 적용 범위

- 문의 수집, 원본 상태 변경, 수동 등록·재요청, 전송 및 수집기 실행 검사와 타입·린트·배포용 빌드를 통과했다. 합성 DB로 실제 화면의 마지막 열, 등록중 중복 클릭 차단, 연결 오류 안내, 일반 계정의 조회 전용 표시를 확인했다.
- 운영 원본에서는 수집 DB에 같은 문의가 저장된 것을 확인한 미처리 33건(접수 21, 미지정 12)을 관리중으로 변경하고 새로고침 후 확인했다. 확인 시점 전체 497건 중 관리중 476건, 없는 번호 20건, 부재중 1건이다. 후자의 21건은 기존 상태를 유지했다.
- 위 원본 변경은 수행 완료했지만 이 PR의 웹·수집기 코드는 아직 운영 배포하지 않았다. 검토한 소스와 이미지로 기존 배포 절차를 적용해야 이후 자동 상태 변경과 등록 버튼이 운영에서 동작한다. 자동 WARP 등록 설정과 운영 DB/계정/비밀값은 이 변경으로 수정하지 않는다.
