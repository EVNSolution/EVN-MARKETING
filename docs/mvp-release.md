# 2026-10-01 발표용 첫 버전

목표는 **원본 신규 문의 → EV&Marketing 조회 → WARP 고객관리 등록**이다.
이 문서는 첫 버전의 범위와 완료 기준이다. 운영 배포 완료나 보안 예외 승인을 뜻하지 않는다.

## 제공 범위

- 로그인 후 문의 내역을 바로 연다. 고객 관리는 기존 WARP로 연결한다.
- 문의일자·시간·상담상태·성함·연락처 조회, 검색, 페이지 이동을 제공한다.
- 기존 수집 지점 이후의 신규 문의를 가져온다. 자동 실행은 수집 완료 후 60분 간격이며, 관리자는 수동 요청도 할 수 있다.
- 기존 수집기와 WARP 전송기를 그대로 사용한다. 연락처가 같은 기존 고객 정보는 보존하고 문의 이력을 추가한다. 이름이 없으면 WARP 수신기의 기존 신원미상 규칙을 따른다.
- 마지막 수집 시각, 수집 상태, 문의별 WARP 등록 완료·대기·보류/오류를 보여준다.
- 자동 등록 설정과 실제 전송 성공을 구분한다. 웹에는 WARP 키를 전달하지 않으며 전송기는 활성 설정과 유효한 키를 모두 확인한다.

자체 랜딩페이지, 광고 유입 추적, 내보내기, 별도 CRM 확장, 화면 개편은 후속 범위다.
기존 고객관리 경로·자료는 삭제하지 않는다. 추가적인 장시간 무중단 검증을 발표 완료 기준으로 요구하지 않지만,
이미 구현된 보안·스키마·복구·중복 방지와 자동 검사 및 배포 차단 조건은 유지한다.

## 확인 순서와 완료 기준

| 순서 | 작업 | 완료 증거 |
| --- | --- | --- |
| 1 | 첫 설치·이미지 수정·MVP 변경 통합 검토 | 검토된 main SHA, 해당 SHA의 CI 결과 |
| 2 | 최종 이미지 게시 및 검사 | 실제 배포 digest와 유효한 검사 결과. 현행 Critical/High/Undefined 차단 유지 |
| 3 | 주소·HTTPS·서버 인증정보 준비 | 실제 주소의 HTTPS 로그인, 인증정보는 SecureString으로만 제공 |
| 4 | 로컬 수집기·자동 재시작 정지, 기존 자료 일관 백업 및 이전 | DB·업로드·사용자·수집 기준점·전송 영수증 보존, 기존 로그인 및 건수 대조, 복원 확인 |
| 5 | 웹 먼저 설치 | `collectorEnabled=false`, `warpDeliveryEnabled=false`로 실제 자료 조회 확인 |
| 6 | 수집 단독 확인 | 로컬 수집기 정지 상태에서 서버 수집기 하나만 실행, 원본 로그인·신규 문의 확인 |
| 7 | WARP 연결·1건 등록·같은 문의 재전송 확인 | 고객 및 문의 이력 중복 없음, 등록 완료 영수증 보존 후 자동 등록 활성화 |
| 8 | 자동 수집 한 주기·재시작·실제 자원 확인 | 다음 수집 실행, 재시작 후 로그인/조회/단일 수집기, 2GiB 서버에서 메모리 부족 없음 |

기존 [최초 설치 절차](cloud-release.md)와 [자료 이전 순서](dedicated-server-plan.md)를 사용한다.
새 배포 도구나 우회 경로를 추가하지 않는다. 전송 보류 문의를 정상 전송으로 표시하거나 영수증을 지우지 않는다.

## 2026-09-28 작업 시작 시 확인

- 전용 AWS 서버와 CLI 접속, 기본 도구는 준비됐다.
- PR #17(최초 설치), #18(이미지 보안 수정)은 통합 작업 시작 시 미병합이었다.
- #18 runtime digest의 ECR 검사에 Critical 0, High 10이 남았다. 최소 기능 채택은 이 위험을 허용하는 결정이 아니다.
- 서비스 DNS/HTTPS, 서버 SecureString 4개, 실제 자료 이전과 서버에서의 수집·WARP 전송은 미완료다.

검토할 코드와 독립된 합성 자료로 동작 검증을 먼저 마친다. 실제 이전 시에는 최신 자료 건수와 상태를 다시 측정한다.
2026-09-30까지 공개 조건을 충족하지 못하면 로컬/녹화 시연을 준비하되 서버 운영 완료로 발표하지 않는다.

## 최소 기능 회귀 검증

`npm run build` 후 `node tests/mvp-browser.mjs`로 실행한다. macOS는 설치된 Chrome의 독립 임시 프로필을,
Linux CI는 런타임 이미지에 포함된 Chromium을 사용한다. 기존 프로필이나 로그인 상태는 변경하지 않는다.
검증은 매번 새 합성 DB와 루프백 웹 서버를 만들고 종료 시 삭제한다. 실제 수집기나 WARP 전송은 실행하지 않는다.

CI에서는 외부 네트워크가 차단된 기존 컨테이너 안에서 동일 검증을 실행한다.
로그인·기본 화면·검색·페이지 이동·WARP 상태 표시·관리자 수동 요청·중복 큐 방지·권한/출처 검증·로그아웃을 확인한다.
실제 외부 연동, 운영 데이터 이전, 이미지 보안 통과를 증명하는 테스트는 아니다.
