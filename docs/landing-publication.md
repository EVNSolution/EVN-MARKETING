# 홈페이지 상담 접수

## 공개 경로와 데이터 흐름

운영 배포 후 사용할 주소는 `https://marketing.cleversystem.ai/landing`이다. 기존 `evnsolution.kr`과 관리자 로그인은 그대로 유지한다. 정적 화면은 `previews/evn-landing`의 검증된 복사본에서 `scripts/build-landing-public.mjs`가 생성한다. `npm run dev`, `npm run build`와 Docker 빌드에 포함된다. 로컬 시연 스크립트는 기존처럼 실제 전송하지 않는다.

방문자는 같은 서버의 `POST /api/external/landing-inquiries`로 공개 폼을 제출한다. 이 경로는 로그인 없이 이름·전화번호·동의를 받기 위한 전용 경로다. 기존 공유키 API `/api/external/leads`를 사용하지 않으므로 `LEADS_INTAKE_API_KEY`를 켜거나 브라우저에 키를 제공하지 않는다. 공개 기능은 `LANDING_INTAKE_ENABLED=true` 및 유효한 `AUTH_URL`·`AUTH_SECRET`이 있을 때만 동작한다. 배포 controller의 `landingIntakeEnabled`는 기본 false이며 기존 수집기·WARP 값과 별개다.

허용 출처, JSON 형식, 4 KiB 본문 제한, 입력 타입, 한국 휴대전화, 필수 동의, 정책 버전, 지역, 숨김 입력을 서버에서 검사한다. UUID 신청번호를 실제 DB에 보관해 응답 유실 후 동일 내용 재전송을 한 건으로 처리한다. 같은 UUID에 다른 내용이 오면 거부한다. 다른 UUID의 재상담은 별도 문의이며 전화번호별 시간당 5건, 전체 시간당 1,000건으로 저장을 제한한다. 이 제한은 CAPTCHA나 네트워크 DDoS 방어를 대체하지 않는다.

접수한 내용은 `Inquiry`의 `evn-landing/evnsolution/pv5` 범위에 저장한다. `LandingReceipt`에 상담 종류·지역·동의 버전·동의 시각을 연결한다. 고객은 만들지 않는다. 문의 내역의 전체 목록과 ‘새 홈페이지’ 필터에서 확인한다. 기존 수집 문의의 WARP 등록·중복 검토 범위는 변경하지 않는다. 새 홈페이지 문의를 WARP에 자동 전송하도록 추가하지 않았다.

## 개인정보와 상담 종료

수집 주체는 원본 하단에 표시된 이브이앤솔루션 주식회사이며 문의 번호는 050-8201-0835다. 원본의 다른 회사명·채용 문구·연령 수집 문구를 사용하지 않는다. 일반 상담은 목적 달성 또는 동의 철회 시 지체 없이 파기하며 다른 법령상 보존 사유가 실제 발생한 자료만 해당 항목·기간에 한해 분리 관리한다. 모든 문의를 일괄 3년 또는 5년 보관한다고 안내하지 않는다.

근거: [개인정보 보호법 제15조·제21조](https://www.law.go.kr/LSW/lsInfoP.do?ancNo=20897&ancYd=20250401&efYd=20251002&lsiSeq=270351). 이 폼의 동의는 상담 목적이며 광고 수신 동의를 포함하지 않는다.

관리자는 ‘상담 종료·개인정보 삭제’에서 확인 후 해당 홈페이지 문의와 동의 관련 내용을 삭제할 수 있다. 무작위 접수번호와 종료 시각만 남겨 오래된 재전송으로 복원되지 않게 한다. 고객·기존 수집 문의를 지우지 않는다. 운영자는 상담 종료를 제때 처리하고, 별도 보존 사유가 있는 자료의 구분 관리와 기존 백업의 접근·만료·복원 후 삭제 반영 절차를 함께 운영해야 한다. 화면에서 삭제됐다는 사실을 SQLite 잔여 페이지·WAL·과거 백업까지 즉시 물리 삭제됐다는 의미로 표현하지 않는다.

## 운영 적용 전 반드시 해결할 배포 조건

`20261007000100_landing_inquiries`는 새 테이블 2개와 인덱스를 추가한다. 기존 테이블이나 데이터를 변경하지 않는다. 현재 원래 운영 `schema-check.mjs`는 **동일 schema만** 허용하므로 이 기능을 바로 배포할 수 없다. 검사 삭제, 임의 이력 수정, 운영 `db push`, seed로 통과시키면 안 된다.

선행 호환 릴리스 `d6d7df889f1a1ca52769a1615e352034f09c3bb8`와 고정된 계약 검사 정책을 준비했다. [선행 릴리스 절차](landing-schema-bridge.md)에 따라 이 이미지를 DB 변경 없이 먼저 배포해야 한다. 기능 코드에도 같은 정책을 포함했다. 기존 테이블에 예상 밖의 컬럼·인덱스가 추가되거나 migration 이력이 다르거나 선행 기능이 없는 이미지와 조합하면 계속 거부한다.

`tests/release-compat.sh`는 이 선행 이미지의 실제 baseline fixture→일관 백업/복원→정식 Prisma migration→기존 행·파일·WARP 이력·migration 이력 보존→구버전 실제 checker의 rollback/자기복구→두 버전 브라우저 쓰기를 검사하도록 변경했다. Linux CI가 이를 실제 통과한 뒤에만 완료로 간주한다. 운영에 적용할 host lock·writer 중지·복원 증거·중단 시 재개 절차는 별도로 완료해야 한다. 원래 운영·수집기를 멈추는 단계 또는 root/sudo 변경이 필요한 경우 사용자가 정한 사전 확인 조건을 적용한다. 이 문서는 그 조건을 승인하거나 gate를 면제하지 않는다.

전환 준비 후에도 `landingIntakeEnabled=false`로 후보를 확인하고, 접수 활성화·정상 저장·관리자 목록 표시까지 확인한 뒤 공개 완료로 보고한다. 실제 고객 이름·전화번호·키·비밀번호를 CI나 PR에 기록하지 않는다.

## Windows 검증

- `npm run test:landing`: 검증 실패 시 무저장, 동의 기록, 12회 재전송, 독립 프로세스 3개 동시 요청, 전송 제한, 타 범위 보존, 개인정보 삭제 및 종료 후 재전송 차단.
- `node tests/landing-browser.mjs`: 격리 체크아웃의 임시 합성 DB에서 실행. 1440/390/320 화면, 실제 폼 저장, 관리자 로그인·필터, 종료 취소·삭제, 외부 요청 및 브라우저 오류 확인.
- Windows의 기존 한글 경로 SWC 문제 때문에 브라우저 검증에는 기존 webpack alias 설정과 paths 없는 개발용 tsconfig를 사용했다. 타입 검사는 별도 검사 config로 수행한다. 운영용 변경에 이 로컬 설정을 섞지 않는다.
- Linux CI에서 Docker 이미지·기존 백업/복원·schema·버전 호환성 검사를 완료해야 한다. Windows sandbox에서는 기존 schema 테스트의 symlink 생성이 EPERM으로 실패하고, 기존 복원 테스트는 Windows 파일 잠금 정리에서 실패했다. 이를 성공으로 계산하거나 테스트를 완화하지 않았다.
