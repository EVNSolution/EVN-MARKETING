# 당근 월별 광고비 정산

관리자 메뉴 **광고비 정산** (`/ad-billing`)에서 한국시간 기준 전월을 기본 조회합니다. 충전과 집행은 각각의 합계이며 두 금액을 비용으로 합산하지 않습니다. 기존 성과 대시보드의 광고비 저장소/수집기와 독립적입니다.

## 원본 가져오기

당근의 올바른 광고계정에서 거래내역 CSV를 내려받고, 파일에 포함된 거래 유형(충전/집행/전체), 조회 시작·종료일, 실제 파일 수집 기준시각(한국시간)을 입력합니다. CSV에 조회 메타데이터가 없으므로 선택한 범위의 **전체 거래**임을 확인해야 합니다. 파일명이나 거래 건수로 범위를 추측하지 않습니다.

원본 열은 `거래 일시,거래 유형,거래 내용,금액` 순서입니다. `2026.09.30. 23:59:59` 형식의 일시, `유상캐시 충전`/`광고캐시 사용`, 카드명·끝 4자리를 포함한 원문 내용, 양의 정수를 받습니다. UTF-8과 RFC4180 인용을 지원하며, 실제 다운로드의 연속된 선두 BOM도 모두 제거한 뒤 읽습니다. 환불/기타 유형·음수·소수·범위 밖 행은 파일 전체를 거절하며 제외하거나 변환하지 않습니다. 빈 원본(헤더만 있는 파일)은 전체 조회를 확인한 유형·기간에 한해 거래 0건을 의미합니다. CSV 2MB/10,000건, 월별 20,000건까지 지원합니다.

미리보기의 변경 전·후 합계/건수/완료 상태/최신 원본 행을 확인한 후 **확인하고 저장**을 누릅니다. 미리보기는 쓰지 않습니다. 같은 파일과 메타데이터를 재전송하면 쓰지 않고 기존 결과를 반환합니다. 새 조회본은 **조회 날짜 범위 + 거래 유형**만 교체합니다. 동일한 충전 행도 실제 여러 거래일 수 있으므로 모두 보존합니다. 더 오래된 수집 기준시각이 새 자료를 덮어쓰거나 같은 기준시각의 다른 내용이 저장되는 경우에는 재확인을 요구합니다. 미리보기 이후 다른 저장이 일어났으면 다시 미리보기 합니다.

수집 당일은 부분일입니다. 집행 행의 시각이 `23:59:59`여도 같은 날 17시 수집본에는 포함될 수 있습니다. 거래일과 조회 종료일이 수집 기준시각의 한국 날짜를 넘으면 거절합니다. 두 유형 모두 월 전체 날짜가 하루 전체 자료로 확인된 지난달까지 **충전·집행내역 준비 완료**, 그 외는 **충전·집행내역 중간집계**입니다. 거래 없는 날은 건수로 누락 판정하지 않으며, 확인된 범위가 없는 유형은 0원 대신 미수집입니다.

## 월말 잔액

거래내역 준비 상태와 별개로 **월말 잔액 확인 필요**를 표시합니다. 기준일은 선택한 월의 마지막 날짜(한국시간)이며, 해당 날 소진 후 잔액을 뜻합니다. 이번 달의 부분 자료를 볼 때도 기준일은 선택 월의 마지막 날짜이며 현재 잔액을 뜻하지 않습니다.

원본 CSV의 4개 열에는 잔액이 없고 확인된 과거 월말 잔액 자료도 없습니다. 당근의 현재 유상·무상 잔액은 과거 월말 값으로 사용하지 않습니다. 현재 잔액과 거래내역의 갱신 시점도 달라 단순 역산하지 않습니다. 내역이 모두 준비됐거나 거래가 0건이어도 월말 잔액은 **미확인**으로 남습니다. 이번 변경에는 잔액 계산, 수동 입력, 저장 형식 변경이 없습니다.

## 엑셀 및 저장

**충전내역 엑셀**과 **집행내역 엑셀**은 실제 XLSX입니다. 원본 4열, 최신 거래순, 숫자 금액, 한국 시각의 날짜 셀, 고정 머리행과 필터를 사용합니다. `자료정보` 시트에 범위·부분일·미수집 날짜·합계·시각을 포함하고, 충전·집행내역 상태와 월말 잔액 미확인 상태·기준일·안내를 따로 기록합니다. 충전·집행내역이 미완료인 파일명에는 `_중간집계`가 붙으며 월말 잔액 상태로 파일명을 바꾸지 않습니다. 미수집 유형은 다운로드하지 않습니다. 조회 후 저장 자료가 바뀌면 새로고침을 요구합니다.

문자열 셀을 명시해 `=`, `+`, `-`, `@`로 시작하는 거래 내용도 수식으로 실행하지 않고 그대로 보존합니다. 원 단위 금액과 유형별 월 합계는 JS 안전 정수이면서 **15자리 이하**여야 합니다. Excel의 숫자 정밀도 한계를 넘는 값을 반올림하지 않고 거절합니다.

`UPLOADS_DIR/_reports/ad-billing/YYYY-MM.json`에 관리자 전용으로 저장합니다. 기존 업로드 제공 경로로는 읽을 수 없습니다. 단일 교차 프로세스 쓰기 잠금, 임시 파일 동기화 후 원자적 교체, 심볼릭/하드 링크 및 손상 데이터 거절을 사용합니다. 비정상 종료로 `writer.lock`이 남은 경우 운영자가 모든 쓰기 프로세스를 멈춘 뒤 확인·복구해야 하며 자동으로 잠금을 탈취하지 않습니다. 기존 uploads 백업 범위에 포함됩니다.

API는 관리자만 접근할 수 있으며 `private, no-store` 응답을 사용합니다. 쓰기에는 동일 출처 및 설정된 AUTH_URL 출처 확인이 필요합니다. 운영 비밀값이나 실거래 자료는 소스·테스트에 넣지 않습니다.

브라우저가 포함된 운영 이미지에는 `LANG=C.UTF-8`, `LC_ALL=C.UTF-8`을 설정합니다. Linux Chromium은 파일명을 네이티브 파일시스템 문자 인코딩으로 변환하므로 기본 C/ASCII 로캘에서는 한글 이름이 `download`로 대체될 수 있습니다. 컨테이너 검사에서 실제 `locale charmap`이 UTF-8인지 확인하고, API의 UTF-8 Content-Disposition과 실제 브라우저 다운로드 이름을 모두 검사합니다. 한글 파일명 기대값은 그대로 유지합니다.

## 라이브러리 및 검증

- [write-excel-file 4.1.1 공식 저장소](https://github.com/catamphetamine/write-excel-file): MIT, Node 18 이상, runtime dependency fflate. 정확한 버전/무결성은 package-lock.json에 고정합니다. 숫자/날짜/문자열 타입과 기본 고정 행 기능을 사용하고, 공식 Feature transform 확장으로 worksheet 필터만 추가합니다.
- `npm run test:ad-billing`: 한국시간 월/윤년, 엄격 CSV, 정밀도, 부분일 재수입, 범위 보존, 중복 거래, 멱등 저장/경합/잠금, 손상·비공개 저장, XLSX 내부 셀/날짜/필터/수식 안전성.
- 기존 CI verify에 정산 테스트를 추가하고, 컨테이너 MVP 브라우저 검사에 관리자/일반/미로그인·출처, 미리보기/저장, 월 전환, 실제 엑셀 다운로드, PC/모바일 검사를 연결합니다. 합성 자료만 사용합니다.

매월 원본 수집·등록과 결과 알림은 Mac 컨트롤 타워의 Codex 예약 작업에서 수행합니다. 웹 서버 자체의 예약 수집 기능은 아닙니다. 화면의 **당근 원본 CSV 가져오기**는 누락·실패 자료를 보완하거나 다시 등록할 때 사용하는 수동 기능입니다. 자동 작업과 수동 보완 모두 공식 조회 범위와 수집 기준시각을 확인하며, 거래내역 준비 완료와 월말 잔액 확인 여부를 구분해야 합니다. 예약 작업 설정·알림과 운영 배포는 컨트롤 타워에서 관리합니다.
