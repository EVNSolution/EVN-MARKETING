배포 대상은 **Marketing 전용 신규 AWS 서버**입니다. WARP 서버 동거와 자원 증설을 기본으로 삼았던 이전 제안은 이 계획에서 대체합니다. WARP에는 기존 공개 HTTPS 문의 API와 전용 인증키로만 연결합니다.

## 채택한 방향

- 웹과 worker는 동일 release 이미지에서 실행하고, 일반 배포에서는 old/new 웹 두 버전과 worker 한 개가 일시 공존합니다. 배포 완료 시 웹/worker digest가 일치해야 합니다.
- 일반 앱 배포는 기존 웹을 유지한 채 후보를 검증하고 프록시를 전환합니다. 프록시·worker 검증 실패 시 최신 DB를 유지하며 이전 호환 버전으로 되돌립니다.
- 초기 Mac 이전, 비호환 schema 변경, 일관된 전체 DB+업로드 백업은 필요한 writer 정지 범위를 명시한 별도 작업입니다. 단일 서버의 호스트 장애까지 고가용성으로 포장하지 않습니다.
- 실제 DB와 업로드는 이미지/소스에 넣지 않고 영속 볼륨에 보관합니다. seed나 `prisma db push`를 컨테이너 시작에 실행하지 않습니다.
- 운영 비밀값은 Marketing 전용 경로에서 역할별로 주입합니다. WARP 전체 SSM 환경값, 기존 BUILDUP 키, WARP 배포 역할을 복사하지 않습니다.
- 로컬 수집기와 서버 수집기의 별개 DB lease는 서로를 막지 못합니다. 최종 전환에서는 로컬 프로세스·자동 실행·자격증명 자동 주입을 중지하고 서버 하나만 운영합니다.

## 현재 증거와 완료 경계

2026-09-22 사용자가 전달한 관리자 답변은 PR #2 계획에 따라 직접 배포 준비를 진행하고 AWS 설정 도움을 받는 방향입니다. 답변을 기다리는 상태로 두지 않고 격리 worktree에서 M1 보안·수집 수정과 합성 검증을 진행합니다. 이 답변을 코드 결함 해소, AWS 자원 생성 또는 운영 검증 완료의 증거로 사용하지 않습니다.

운영 준비 시 관리자와 맞출 값은 아래와 같습니다. 기존 WARP의 권한이나 비밀값을 조회·복사해서 대신하지 않습니다.

| 설정 | 준비안 / 확정할 값 |
| --- | --- |
| 전용 서버 | 서울, Ubuntu 24.04 x86_64, t3.medium / 암호화 gp3 40 GB는 측정 후보. 리소스 생성 전 사양·예산·VPC/서브넷·보안 그룹 및 담당 범위 확정 |
| 접속 주소 | `marketing.cleversystem.ai` 제안 주소의 사용 가능 여부, DNS 관리 주체, 신규 고정 IP와 HTTPS 인증서 |
| 배포 권한 | Marketing 전용 ECR, GitHub 운영 environment/OIDC 역할, 전용 EC2 역할과 대상 제한 SSM 명령. 실제 ARN/ID는 M3 구성에 반영 |
| 비밀값 | Marketing 인증 비밀값, 원본 로그인, WARP 전용 키의 승인된 SecureString 이름과 주입 담당. 값은 PR/메시지/파일에 기재하지 않음 |
| 백업·관측 | 별도 암호화 백업 보관/복원 경로, 보존 기간, 장애·백업 실패 알림 수신자 |

M1 이후 M2 운영 CLI·상태 확인·중단/버전 호환, M3 배포/복귀 자동화, M4 이전/복원 리허설, M5 실제 운영 전환 순서로 진행합니다. 외부 리드 수신 API는 R8 수정·검증 전까지 키를 비워 둡니다. 프록시 캐시/본문 제한과 실제 로그아웃 후 파일 접근, 최종 이미지 검사 및 Z01–Z10은 별도 증거가 필요합니다.

이번 M1 수정은 서버 소유 첨부 경로, 고객별 경로 경계·symlink 차단, 교체/삭제 실패 시 보존 및 변경 충돌 검사, 비공개 캐시, 업로드 크기·형식 검증, 내부 복귀 경로와 수집기 활성화·재로그인 복구를 포함합니다. 합성 파일/DB 기반 보안·수집·전송·계약 검사, 타입 검사와 로컬 빌드를 통과했습니다. lint는 오류 0/기존 경고 4이며, 전체 npm audit의 기존 high 5/critical 0은 남아 있습니다. 이 결과는 실제 원본 로그인이나 운영 배포 검증이 아닙니다.

업로드는 파일당 10 MiB, 고객별 50 MiB로 제한하며 본문 길이가 없는 업로드는 411로 거부합니다. 현재 용량 잠금은 웹 프로세스 내부에서만 직렬화하므로, M2에서 두 웹 슬롯의 동시 업로드 총량과 프록시 본문 제한을 검증·보완하기 전에는 운영 준비 완료로 표시하지 않습니다. 실제 프록시를 거친 브라우저 파일 업로드도 확인해야 합니다.

[기존 Linux PR CI](https://github.com/EVNSolution/EVN-MARKETING/actions/runs/35194264731)는 a7bf7d0의 합성 수집/DB/전송/계약/타입, 이미지 빌드, 비루트 Chromium 및 컨테이너 기동을 검증했습니다. 실제 서버의 용량·원본 로그인·시간당 실행·재부팅·무중단 배포·백업 복원을 검증한 것은 아닙니다.

문의 409건 / WARP 등록 406건 / 충돌 보류 3건은 과거 개발자 기록입니다. 현재 DB를 직접 검증한 집계가 아니며, 이전 때 최신 모든 테이블·receipt·파일을 다시 대조합니다. 보류 건의 고객을 임의 선택하거나 병합하지 않습니다.

PR #2는 문서·검토 결과만 게시한 계획 PR이며, 후속 변경에서 실제 코드 수정을 진행합니다. 현재 서버 생성, DNS/IAM/운영 비밀값 변경, 실제 고객 자료 이전, 이미지 게시, 원격 머지와 운영 배포는 수행하지 않았습니다. 기존 Compose를 실행했다고 blue/green과 아래 완료 기준이 구현된 것으로 간주하지 않습니다.

## 운영 완료 기준

1. PR #1의 공개 전 보안/수집 결함 수정과 해당 회귀 검사를 통과합니다.
2. source SHA와 이미지 digest, 전용 HTTPS, 기존 사용자 로그인, 비인증 접근 차단을 확인합니다.
3. DB/업로드/전송 이력 이전 동일성과 복원 가능한 오프호스트 백업을 확인합니다.
4. 원본 headless 로그인, 신규 수집, 승인된 1건 최초/재전송 중복 방지와 WARP 화면을 확인합니다.
5. 다음 실제 1시간 주기, 재부팅 복구, 단일 worker를 확인합니다.
6. 웹 두 버전+Chromium의 자원 peak와 무중단 전환/실패 rollback 인수 검사를 통과합니다.

WARP의 별도 기능 변경/배포는 이 Marketing 계획의 구현 완료나 배포 완료에 포함하지 않습니다.
