## 실제 수집 과정에서 발견하고 수정한 문제

9월 15일 10:10(KST) 사용자가 수집용 Chrome에서 원본 로그인을 완료했고 수집기가 이를 인식했다. 최초 수집과 수동 재시도 모두 첫 페이지 처리 중 `page_error`로 실패했으며, 이 시점의 Inquiry는 0건이다. 실문의 이관 성공으로 표시하지 않는다.

실패 원인은 `tsx` 변환이 브라우저로 전달되는 행 추출 함수 안에 삽입한 `__name` 보조 함수였다. 브라우저에는 해당 함수가 없어 실제 행 추출이 즉시 실패했다. 이름 있는 내부 함수를 제거해 수정했으며, Node VM에서 브라우저 콜백을 별도 환경으로 직렬화해 실행하는 합성 DOM 검사로 수정 전 실패와 수정 후 통과를 확인했다. 이 검사는 `npm run test:inquiries`에 포함했다. 수정본을 반영하려면 수집기를 재시작하고 새 임시 브라우저에서 다시 로그인해야 한다.

기존 잠금 검사도 앞선 검사에서 남은 실행 소유권을 명시적으로 해제하도록 수정했다. 실제 시각이 고정된 시험 시각을 지나면 실패하던 검사 간 상태 간섭을 제거했으며, 전체 동기화 검사와 새 직렬화 검사 모두 통과했다. 10:17(KST)에 수정된 수집기를 실행해 새 로그인 대기 상태를 확인했다. 실제 최초 수집 및 건수 대조는 새 창의 재로그인 이후 확인한다.

재로그인 후에는 원본의 초기 로딩 중 `총 0개`가 표시되는 추가 문제가 드러났다. 10:18 실행은 `empty_loading`으로 실패했고, 10:19 재시도는 0건 성공으로 잘못 기록됐다. 원본을 새로 조회해 380건을 확인했으므로 잘못된 0건 실행은 삭제하지 않고 `failed / empty_loading`으로 정정하며 성공 시각을 취소했다. 조회 요청이 끝난 뒤 실제 행 또는 명시적인 빈 결과가 나타날 때까지 기다리고 그 이후 총수를 읽도록 보완했다. 초기 0건에서 행이 나타나는 경우, 실제 0건, 기존 1건의 합성 회귀 검사와 전체 동기화 검사를 통과했다.

로컬 앱은 기본 3000 포트, 수집 프로그램은 별도 프로세스로 실행한다. 둘 다 Mac이 켜져 있고 해당 프로세스가 유지될 때 동작한다. 프로그램을 다시 실행할 때는 기존 실행 여부를 먼저 확인한다.
