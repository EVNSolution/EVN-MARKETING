# 문의 연락처 중복 표시

미등록 문의의 연락처가 앞서 수집된 문의 또는 WARP 고객의 기본 연락처와 같으면, 문의 목록에 클릭할 수 없는 `중복` 표시와 사유를 노출한다. 두 곳에서 모두 발견되면 두 사유를 함께 표시한다. 하이픈·공백과 한국 휴대전화 `+82 10…` / `010…` 표기를 정규화한다. 이름이나 번호 뒷자리만으로 판단하지 않는다.

이미 연동됐거나 사용자가 등록을 확인한 문의는 `등록완료`를 유지한다. 모든 원본 문의를 보존한다. 수집 내 중복은 페이지·검색과 관계없이 같은 출처 범위 전체에서 먼저 수집된 문의를 기준으로 하며, 수집 시각이 같으면 문의일자·시간·원본 ID·내부 ID 순서로 기준 문의를 정한다.

## 연동 및 오류 처리

- 기존 worker 전용 키로 `POST /api/external/marketing-inquiries/check`를 사용한다. 웹 프로세스에는 키를 주지 않는다.
- 최대 50건씩 조회하며 신규/미확인 문의를 먼저 확인한다. 성공 결과는 5분 뒤 갱신하고, 실패는 1분 뒤 다시 확인한다. 10분 이상 지난 미중복 결과로는 화면에서 등록을 요청할 수 없다.
- 고객의 존재 여부만 받는다. 해당 원본 문의의 기존 수신 기록이 있을 때만 receipt를 받아 로컬 등록완료를 복구한다. 다른 고객의 이름·ID 등은 조회 결과로 받지 않는다.
- 조회 오류/구버전 WARP/잘못된 응답은 `중복 확인 중`으로 남긴다. 잘못된 과거 연락처 한 건이 나머지 일괄 조회를 막지 않는다.
- 목록 외의 직접 등록 요청도 중복이면 409로 거절한다. 수집기 자동·수동·pilot 전송은 수집 내 중복을 제외하고, 실제 전송에는 `rejectExistingCustomer: true`를 보낸다. WARP가 쓰기 트랜잭션 안에서 연락처를 다시 확인하므로 조회 이후 새 고객이 등록된 경우도 차단한다. 같은 원본 문의 재전송은 기존 receipt가 우선이다.
- 복구 도구도 동일한 전송 방어를 사용한다. 고객은 남고 원본 수신 기록만 삭제된 경우 `phone_exists`로 중단할 수 있으며, 기존 고객에 이력을 강제로 추가하지 않는다.

## 배포 순서와 현재 경계

1. WARP 담당자가 새 조회 권한과 전송 방어를 검토한 뒤 공식 WARP 배포 절차로 반영한다. 이전 연동 승인은 이번 조회 기능의 승인으로 간주하지 않는다.
2. Marketing 운영 DB의 정합성 있는 백업과 복원본에서 `20260930000100_warp_phone_check`를 검증한다. 문의에 nullable `warpPhoneStatus`, `warpPhoneCheckedAt` 두 열만 추가한다. 기존 문의/receipt/계정/업로드는 변경하지 않는다.
3. DB 변경에 대한 별도 전환 검토 후 Marketing을 배포한다. 기존 `schema_change_requires_review` 차단은 그대로 유지했으므로 이번 변경을 일반 앱 배포 명령으로 바로 적용할 수 없다. 운영 중인 DB에 직접 마이그레이션하거나 manifest를 바꿔 차단을 우회하지 않는다.
4. 배포 후 완료 상태 보존, 수집 내/WARP/양쪽 중복, 정상 신규 문의, 조회 실패 표시와 재시도를 확인한다. 운영 고객 생성 테스트는 합의된 문의만 사용한다.

로컬 합성 데이터 검증과 운영 배포는 구분한다. CI의 구버전 화면 검사는 확장된 합성 DB에서 수행하되, 이전/현재 schema 간 일반 배포가 여전히 거절됨을 별도로 확인한다. 이 검사는 운영 DB 전환 승인을 대신하지 않는다. 운영 DB는 이 기능 개발 중 변경하지 않았다.

## 검증

`npm run test:inquiries`, `npm run test:warp-delivery`, `npm run test:warp-recovery`로 중복 분류·등록 방어·실패 처리·기존 수신 기록 복구를 검사한다. `npm run test:schema`는 열 추가 후 기존 문의/receipt 보존 및 기존 배포 차단을 검사한다. 빌드 후 `node tests/mvp-browser.mjs`는 합성 DB로 화면의 세 가지 중복 사유, 버튼 부재, 등록 API 409, 정상 문의의 등록 버튼과 권한을 검증한다.
